# Translate Every Screen and Turn On Switching — Implementation Plan (2 of 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every user-facing string in the app (screens, constants, hooks' messages) into catalogs with fr/de/it/es translations. Then turn on the language picker and browser detection, so a user can work entirely in their language. New screens must be covered automatically.

**Architecture:** Builds on plan 1 (react-i18next, `src/locales/<lng>/<ns>.json`, `.meta.json`, `i18n:check` gate, `extracted.json` lint, `AGENTS.md` rules). Adds: lazy-loaded non-English catalogs, a shared `format` helper for dates and numbers, a logged-out language switcher, and a **pseudo-locale render test** that finds any English text left on a rendered screen. Each area task extracts one group of files, hand-writes translations, adds the files to `extracted.json`, and adds a pseudo-locale test for that area. The last task flips the switch and turns `extracted.json` into globs, so every new file is linted by default.

**Tech Stack:** React 19, TypeScript, Vitest + Testing Library, i18next/react-i18next, ESLint (`eslint-plugin-i18next`).

**Spec:** `docs/superpowers/specs/2026-11-13-localization-design.md`
**Prior plan + follow-ups:** `docs/superpowers/plans/2026-11-13-i18n-foundation.md`, `docs/superpowers/plans/2026-11-13-i18n-foundation-followups.md`

**Out of scope (plan 3):** clinical chart PDF (`src/utils/pdfGenerator.ts`, `src/utils/pdf/**`), emails / edge functions / Supabase auth templates, practice client-communication language and seeded-default detection, the legal "English governs" notice, and mapping server error codes. **Plan 4:** everything after speech-to-text in voice (`aiAutofill.ts` normalisation and prompts, `deepgramVoice.ts`, `voiceKeyterms.ts`). Visible chrome in `VoiceInputButton.tsx` (buttons, labels, status text) **is** in scope here.

## Global Constraints

- App languages: `en`, `fr`, `de`, `it`, `es`. English is the source and its rendered text must not change. Existing component tests pass with their English assertions unmodified.
- Translations are hand-written by the implementer (there is no API key). Use formal address (vous / Sie / Lei / usted), follow `src/locales/glossary.json` terms exactly, keep `{{placeholders}}` identical, and use `_one`/`_other` plurals plus `_many` for fr/it/es. Stamp with `npm run i18n:translate -- --rehash`. Stale keys must be named `lng:ns:key`.
- Adding a namespace means adding it to `src/locales/<lng>/<ns>.json` for all five languages, `NAMESPACES` in `src/i18n/config.ts`, and `src/i18n/i18next.d.ts`.
- Every extracted file goes into `src/i18n/extracted.json`. The lint must pass.
- Operator-only surfaces stay English and lint-exempt: `src/components/AdminPanel.tsx`, `AdminChartList.tsx`, `AdminChartViewer.tsx`.
- Clinical codes (AVDC abbreviations, Triadan numbers) stay as codes. Their descriptions are translated.
- Free text that users type is never translated.
- Dates and numbers shown in the UI use the active language through `src/i18n/format.ts`, never bare `toLocaleDateString()`.
- `npm test` and `npm run build` pass after every task. Stage files by path. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `LANGUAGE_SWITCHING_ENABLED` stays `false` until Task 11.

## Review Focus

1. **Text built outside JSX** (`const label = 'Save changes'`, ternaries, arrays of option labels, `title` built with template strings). The lint misses these, so the pseudo-locale test in each area must render the states where they appear → every area task's `*.i18n.test.tsx`.
2. **Sentence assembly**: `t('a') + name + t('b')` breaks word order in de/fr. Use one key with `{{placeholders}}` or `<Trans>` → reviewers check each area diff; Task 1's lint test bans `t(...) + ` concatenation in extracted files.
3. **Plural and count text** ("3 charts", "1 tooth"): it must use `count` plurals with fr/it/es `_many` → `i18n:check` enforces it, and area tests render count = 1 and count = 3.
4. **Date and number formats**: a French user must see `19 juil. 2026` / `1 234,5`, not US formats → Task 1 `format.test.ts`, plus area tests asserting a formatted date in `fr`.
5. **Logged-out pages** (landing, login, reset password) follow the browser or a saved choice before any account loads, without flashing English → Task 1 tests `uses saved logged-out language` and `no English flash while prefs load`.

### Task 1: Shared infrastructure (lazy catalogs, format, logged-out language, pseudo-locale test kit)

**Files:**
- Modify: `src/i18n/index.ts`. English loads eagerly; fr/de/it/es/pt load on demand through `import.meta.glob` (non-eager) with an `i18next-resources-to-backend`-style loader, or with `addResourceBundle` called before `changeLanguage`. Tests may load everything eagerly.
- Create: `src/i18n/format.ts`, `src/i18n/LanguageSwitcher.tsx`, `src/i18n/testing/pseudo.ts`
- Modify: `src/i18n/useAppLanguage.ts`, `src/EntryGrid.tsx` (wiring only), `scripts/i18n/check.ts` (flag stray language directories and stray namespaces, such as `pt/common.json`, as `extra`), `eslint.config.js` (ban `t(...) +` / `+ t(...)` string concatenation in extracted files using `no-restricted-syntax`)
- Test: `src/i18n/format.test.ts`, `src/i18n/useAppLanguage.test.tsx`, `src/i18n/testing/pseudo.test.tsx`, `src/i18n/LanguageSwitcher.test.tsx`, additions to `scripts/i18n/check.test.ts` and `scripts/i18n/lint.test.ts`

**Interfaces (produced):**
- `formatDate(value: Date | string, style: 'short' | 'medium' | 'long' = 'medium', lng = i18n.language): string`. A `yyyy-mm-dd` string is parsed as a local date. Unparseable input is returned unchanged.
- `formatDateTime(value: Date | string, lng?): string`
- `formatNumber(n: number, opts?: Intl.NumberFormatOptions, lng?): string`
- `formatList(items: string[], lng?): string`. Uses `Intl.ListFormat` conjunction. `en` uses `en-GB` (no Oxford comma) to match current text.
- `useAppLanguage(saved: AppLanguage | null, loaded: boolean): AppLanguage`. While `!loaded`, it uses the localStorage `app.language` value (written whenever the user picks a language). This avoids a browser-language flash for users who chose one. It awaits the lazy catalog load before `changeLanguage`.
- `<LanguageSwitcher compact? />`: a `<select>` of `LANGUAGE_NAMES` that writes `app.language` to localStorage and changes language. It renders nothing while `LANGUAGE_SWITCHING_ENABLED` is false.
- `installPseudoLocale(): Promise<void>`: registers language `'xx'`, built from every `en` namespace by wrapping each value as `⟦value⟧` with placeholders preserved, then switches to it.
- `restoreLocale(): Promise<void>`: switches back to `en`.
- `findUntranslated(root: HTMLElement, allow: (string | RegExp)[] = []): string[]`: walks text nodes and the `title` / `placeholder` / `aria-label` / `alt` / `value` (buttons only) attributes. It returns every trimmed string that contains a letter outside `⟦…⟧` segments and isn't matched by `allow`. Test fixtures pass their own user data (pet names, emails) in `allow`.

### Area tasks (2–10): shared shape

Each area task:
1. Extracts every user-facing string in its files into the listed namespace(s). That covers JSX text, attributes, toasts, dialog options, error messages shown to users, option and label arrays, and text built in hooks or utils that reaches the UI. Dates and numbers go through `format.ts`.
2. Hand-writes fr/de/it/es and stamps them.
3. Adds every file to `src/i18n/extracted.json`.
4. Adds `src/<area>.i18n.test.tsx` (or one next to the components). It renders each listed component in its main states (empty, filled, error, count = 1 and count = 3 where counts appear) under `installPseudoLocale()`, and asserts `findUntranslated(container, fixtureData)` equals `[]`. It also asserts one formatted date or number in `fr` where the area shows one.
5. Keeps existing tests passing unchanged.

The steps for each area task:
- [ ] **Step 1: Write the area's pseudo-locale test.** It renders the components with fixture data, under `installPseudoLocale()`.
- [ ] **Step 2: Run it.** Expected: FAIL, listing the English strings found.
- [ ] **Step 3: Extract** into the namespace(s) and write the translations.
- [ ] **Step 4: Run** `npx vitest run <area tests> && npm test && npm run build`. Expected: PASS, with `findUntranslated` → `[]`.
- [ ] **Step 5: Commit** "i18n: extract <area>".
