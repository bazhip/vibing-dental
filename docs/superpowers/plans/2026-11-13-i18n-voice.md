# Voice Dictation in French, German, Italian, Spanish — Implementation Plan (4 of 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A vet dictating in French, German, Italian or Spanish, with English codes mixed in, gets the same chart results as a vet dictating in English. This is the owner's decision "full parity at launch".

**Architecture:** Every stage of the voice pipeline becomes language-aware, keyed on the app language (`i18n.language`):
1. **Speech-to-text:** Deepgram `nova-3-medical` with `language=multi` for fr/de/it/es. Per Deepgram's docs, the medical model's multilingual mode covers es/fr/de/it and handles code-switching, so vets can say "T/FX/CCF" in a French sentence. English keeps today's exact URL. A per-language table allows switching a language to monolingual `nova-3` later without code changes.
2. **Keyterms:** English codes and terms plus the glossary's native clinical terms for that language, within Deepgram's limits (≤100 terms, ≤500 tokens).
3. **Spoken numbers:** a new per-language module turns spoken numbers into digits. It handles digit-by-digit ("un zéro quatre", "eins null vier") and compound hundreds ("cent quatre", "hundertvier", "centoquattro", "ciento cuatro") for every valid Triadan tooth, plus scores and millimetres.
4. **Cleanup:** `normalizeTranscript(raw, lng)` gets per-language score terms, unit words, spelled letters and "slash" words. The filler filter `chunkWorthSending(chunk, lng)` and `isPerioOnlyText` become multilingual.
5. **AI prompt:** it tells Claude the dictation language and adds per-language few-shot examples that map native phrasing to the same tool calls.
6. **Evaluation:** per-language transcript fixtures, each with expected cleaned text and expected chart actions. Offline tests run in `npm test`. A live replay (`npm run replay -- --lang fr --expect …`) scores extraction against the expected actions and reports a parity number. It needs an Anthropic key, so the owner runs it.

**Tech Stack:** TypeScript, Vitest, Deepgram streaming (WebSocket URL params), Anthropic Messages API (prompt built client-side, proxied by `supabase/functions/ai-autofill`), tsx replay script.

**Spec:** `docs/superpowers/specs/2026-11-13-localization-design.md`, Surfaces → Voice dictation: "Owner decision: full parity at launch … Must handle vets mixing English codes into native speech. Accuracy bar: per-language replay suite passes at the same rate as English."

## Global Constraints

- **English voice behaviour must stay byte-identical:** the Deepgram URL, `normalizeTranscript` output, `chunkWorthSending`, `isPerioOnlyText`, the system prompt text and few-shot examples, and request bodies. All existing voice tests (`src/utils/aiAutofill.test.ts`, `deepgramVoice.test.ts`, `src/components/voice.i18n.test.tsx`, `VoiceInputButton.test.tsx`) pass unchanged.
- Languages: `en`, `fr`, `de`, `it`, `es`. Pass the language explicitly, as `lng: AppLanguage`. Pure functions never read `i18n.language`.
- **Clinical terms come from `src/locales/glossary.json`.** Native terms for keyterms and score words are taken from it, never hand-copied, so terminology stays consistent.
- **Tool-call values stay language-neutral:** Triadan numbers, field names, AVDC codes and exam area ids. Free-text comment values keep the dictated language.
- No API keys are available here (Anthropic, Deepgram). Tests never call real APIs. Live replay is an owner action, and the plan and PR say so.
- Edge functions: only `ai-autofill` may need changes. Check it with `cd supabase/functions && DENO_NO_PACKAGE_JSON=1 deno check ai-autofill/index.ts`. Never deploy.
- `npm test` and `npm run build` pass after every task. Stage files by path. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Tooth number versus score:** "mobilité trois un zéro trois" means mobility 3 on tooth 103, not tooth 310. Covered by Task 3's per-language versions of the existing English score-then-tooth tests.
2. **Compound numbers that aren't teeth:** "cent quatre-vingt-dix" (190) is not a valid Triadan number and must stay as given, not be forced into a tooth. "deux cent neuf" → 209. Covered by Task 2's exhaustive tests: every valid tooth in every language, plus invalid numbers left alone.
3. **English codes inside native speech:** "dent cent quatre T slash FX slash CCF" → "dent 104 T/FX/CCF". Covered by Task 3's mixed-language tests.
4. **Keyterm budget overflow:** Deepgram errors above 500 tokens. Covered by Task 1's budget test using a conservative token estimate (characters/3), per language.
5. **German compounds and Swiss/Austrian forms:** "einhundertvier", "hundertvier", "eins-null-vier" all → 104. Swiss "zwei-null-neun" also works. Covered by Task 2.

### Task 2: Spoken numbers per language

**Files:**
- Create: `src/utils/voice/numbers.ts`
- Test: `src/utils/voice/numbers.test.ts`

**Interfaces:**
- `NUMBER_WORDS: Record<AppLanguage, { digits: Record<string, number>; … }>`, internal.
- `replaceSpokenNumbers(text: string, lng: AppLanguage, opts?: { scoreTerms?: RegExp; unitTerms?: RegExp }): string`. This is the per-language equivalent of the English digit-word passes. For `en` it delegates to the existing English logic, which is extracted unchanged from `normalizeTranscript`.
- `isTriadan(n: number): boolean`. Permanent teeth: quadrants 1–4 with positions 01–11. Deciduous teeth: quadrants 5–8 with positions 01–08 (dogs and cats; reuse the app's existing tooth data where possible).

**Algorithm, per language:**
- **Digit-by-digit sequences** of 2–3 digit words become a number. Include the language's zero words: fr "zéro", de "null", it "zero", es "cero". Include the common "o/oh" equivalents only if speakers use them; fr/es/it don't, so leave them out.
- **Compound hundreds** become a number when the result is a valid Triadan number, or is followed by a unit, or is preceded by a score term:
  - fr: "cent quatre", "deux cent neuf", "trois cent dix", "quatre cent onze", "cinq cent quatre". Handle "cent un", "cent onze" and hyphenated forms.
  - de: "hundertvier", "einhundertvier", "hundert vier", "zweihundertneun", "dreihundertzehn", "vierhundertelf". Handle "hundertundvier".
  - it: "centoquattro", "cento quattro", "duecentonove", "trecentodieci", "quattrocentoundici", and elided forms such as "centuno".
  - es: "ciento cuatro", "doscientos nueve", "trescientos diez", "cuatrocientos once", "quinientos cuatro".
- **Single number words** become digits after a score term or before a unit (mirrors `SCORE_WORD_RE` / `UNIT_WORD_RE`). This covers 0–15 for millimetres.
- Accents and case are ignored in matching ("zero" and "zéro" both match). Deepgram's numerals output ("104") passes through unchanged.

**Tests:**
- For each of fr, de, it, es, and for **every** valid Triadan number, generate the language's canonical compound form and its digit-by-digit form with a small per-language number-to-words helper in the test file. Both must map to the number.
- Invalid numbers (190, 120, 512) are not turned into teeth unless a unit or score term is present.
- Score-then-tooth: fr "mobilité trois un zéro trois" → "mobilité 3 103". The same in de, it and es.
- `replaceSpokenNumbers(x, 'en')` equals the old English passes for every line of `scripts/fixtures/sample-transcript.txt` and for every English test input in `aiAutofill.test.ts`.

**Commit** "voice: spoken numbers in fr/de/it/es".

- Create: `src/utils/voice/terms.ts`. It builds per-language score-term, unit and slash regexes from the glossary and a small explicit table:

### Task 5: Per-language evaluation fixtures and replay scoring

**Files:**
- Create: `scripts/fixtures/voice/{en,fr,de,it,es}/` holding `transcript.txt` and `expected.json`. Each transcript is a realistic dictation (≥25 utterances) covering:
  - periodontal values across multiple teeth
  - a fracture with an AVDC code, said as a code and as words
  - extractions (definitive and speculative)
  - missing teeth
  - exam findings (normal and abnormal with a comment)
  - a nerve block with a drug and mL
  - a correction ("scratch that")
  - a tech speaker
  - deciduous teeth
  - English codes mixed into native speech

  `expected.json` lists the expected `AiAction`s after final check, which is the target chart, plus the expected cleaned text per line. The English fixture is derived from the existing `sample-transcript.txt` and extended to the same coverage. The other four express the **same clinical content**, so parity is measurable.
- Create: `scripts/i18n/voiceEval.ts`. Exports `scoreActions(expected: AiAction[], actual: AiAction[]): { precision; recall; f1; missing; extra }`, comparing order-insensitively on name and normalized input, with comment text compared loosely (contains key code/number).
- Modify: `scripts/replay-transcript.ts`. Add `--lang <lng>`, which threads into normalize, filter and prompts, and `--expect <file>`, which prints the score and the missing and extra actions. Add `--all-langs`, which runs every fixture and prints a parity table (F1 per language, with English as the baseline).
- Test: `scripts/i18n/voiceFixtures.test.ts` (offline, in `npm test`):
  - For every language, `normalizeTranscript` on every line equals the fixture's expected cleaned text.
  - `chunkWorthSending` keeps every line that has a finding.
  - Every expected action is valid (`invalidReason === null`).
  - The five fixtures have the same clinical content: the multiset of (action name, triadan, field, mark) is identical across languages, ignoring free-text.
- Test: `scripts/i18n/voiceEval.test.ts` for `scoreActions`.

**Owner action (report and PR):** run `ANTHROPIC_API_KEY=… npm run replay -- --all-langs --expect`. Accept when each language's F1 is within 0.05 of English. Record the table in the PR, or in a follow-up if run after merge.
