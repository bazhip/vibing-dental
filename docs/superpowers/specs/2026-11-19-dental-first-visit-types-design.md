# Dental-first visit types

Patients have one visit history. Each visit has its own type, date, saved notes and export. Dental procedure comes first in the chooser and remains the default for existing data and immediate dental workflows. Consultation is a second selectable type for enabled practices. GP examination and phone calls are future visit types.

The New visit chooser follows GitHub's new issue template picker. Show both visit types directly with short descriptions and one Start visit action. Open each type's own workspace and show a type label next to the date in history. Put the export action in the current visit. Consultation uses its existing templates, a standalone note PDF and the shared handoff. Dental retains its clinical chart PDF and original section navigation. ScribbleVet's note template and export flows informed the functional hierarchy.

A dental recording applies to the full visit. The active tab supplies context to the established dental extraction pipeline. Retain the protected English request inputs and current conflict review. Add coverage for clinical fields outside the existing parser through separate clinician review where needed.

Existing untyped records are dental visits. Keep older dental, consultation and GP findings in saved records and exports. Starting either type shares patient identity only, except that a new dental procedure brings forward missing teeth from the most recent dental visit. A consultation and dental procedure on the same date are separate visits. The extension opens and transfers the chosen record.
